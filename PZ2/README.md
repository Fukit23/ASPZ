# Практичне завдання 2

Цей репозиторій містить рішення завдань з дослідження сегментів пам'яті, роботи стека викликів та управління віртуальною пам'яттю в ОС Linux.

## Вимоги до середовища

* **ОС:** Linux (наприклад, Ubuntu) або середовище WSL.
* **Компілятор:** `gcc`.
* **Інструменти:** `size`, `gdb`, `pstack` (або `gstack`).

## Опис завдань

### Завдання 2.2: Дослідження сегментів файлу
**Файл:** '2,2.c'

Це завдання виконується покроково для спостереження за тим, як різні типи змінних впливають на розмір сегментів програми (text, data, bss) та загальний розмір файлу.

#### Крок 1. Базова програма
Створюємо простий файл 2,2.c:
```bash
#include <stdio.h>

int main() {
    printf("Hello\n");
    return 0;
}
```
Команди для перевірки:
```bash
gcc 2,2.c -o 2,2
ls -l 2,2
size 2,2
```

Аналіз: 
Утиліта size покаже базові розміри сегментів для порожньої програми.

#### Крок 2. Глобальний неініціалізований масив
Додаємо глобальний масив a1:
```bash
#include <stdio.h>

int a1[1000];

int main() {
    printf("Hello\n");
    return 0;
}
```

Аналіз:
Після компіляції та виклику size ви побачите, що розмір сегмента BSS (неініціалізовані дані) збільшився приблизно на 4000 байт (1000 елементів int по 4 байти). Загальний розмір файлу на диску (ls -l) майже не зміниться, оскільки BSS не зберігає самі нулі у файлі, а лише вказівку ОС виділити цю пам'ять при запуску.

#### Крок 3. Глобальний ініціалізований масив
Змінюємо оголошення, додавши початкове значення:
```bash
#include <stdio.h>

int a1[1000] = {1};

int main() {
    printf("Hello\n");
    return 0;
}
```

Аналіз:
Тепер масив перемістився з сегмента BSS у сегмент Data. Утиліта size покаже збільшення data на ~4000 байт і зменшення bss. Загальний розмір виконуваного файлу (ls -l) також збільшиться, оскільки ініціалізовані дані жорстко зашиваються в бінарний файл.

#### Крок 4. Локальні масиви всередині функції
Додаємо функцію з локальними масивами:

```bash
#include <stdio.h>

int a1[1000] = {1};

void f1() {
    int l1[1000];
    int l2[1000] = {1};
}

int main() {
    f1();
    printf("Hello\n");
    return 0;
}
```
Аналіз:
>Дані не розташовуються всередині виконуваного файлу як статичні сегменти.

>Вони не залишаються у сегментах Data чи BSS. Локальні змінні виділяються динамічно в сегменті Stack (стек) лише під час виконання функції f1().

>Різниця між ініціалізованим і ні: Неініціалізований локальний масив просто зсуває вказівник стека. Ініціалізований масив робить те саме, але додатково процесор виконує інструкції коду (text) для заповнення цієї ділянки пам'яті значеннями під час виклику функції. Розмір самого файлу від розміру локальних масивів не зростає.

#### Крок 5. Вплив прапорців компіляції
Перевіряємо зміни з різними параметрами компілятора.

Для налагодження (Debug):
```bash
gcc -g 2,2.c -o 2,2
ls -l 2,2
size 2,2
```

Аналіз: 
Загальний розмір файлу (ls -l) різко збільшиться, оскільки компілятор додає масивні таблиці символів та налагоджувальну інформацію (щоб працював gdb). Сегменти text, data, bss зміняться несуттєво.

Для максимальної оптимізації:

```bash
gcc -O3 2,2.c -o 2,2
ls -l 2,2
size 2,2
```

Аналіз: 
Компілятор може "викинути" функцію f1() або масив a1, якщо виявить, що вони ніде не використовуються для корисних обчислень (Dead Code Elimination). Це призведе до зменшення розміру сегмента коду (text) та даних. Загальний розмір файлу буде мінімальним.

### Завдання 2.3: Розташування сегментів пам'яті
**Файл:** '2,3.c'

Програма визначає та виводить адреси ключових сегментів пам'яті процесу під час виконання:

- Text (код)

- Data (ініціалізовані дані)

- BSS (неініціалізовані дані)

- Heap (купа)

- Stack (стек)

#### Запуск:
```bash
gcc 2,3.c -o 2,3
./2,3
```

### Завдання 2.4: Аналіз стека процесу
**Файл:** '2,4.c'

Програма виконує кілька вкладених викликів функцій і блокується системним викликом pause(). Це дозволяє підключитися до процесу ззовні та дослідити його стек.

#### Інструкція з перевірки:

1. Скомпілюйте програму:

```bash
gcc 2,4.c -o 2,4
./2,4
```

2. Запустіть програму у фоновому режимі:

```bash
./2,4 &
```

3. Знайдіть PID процесу:
```bash
pidof 2,4
```

4. Перегляньте стек викликів (замініть '<PID>' на отриманий номер):

```bash
sudo pstack <PID>
```
Або через GDB:
```bash
sudo gdb -p <PID>
```

5. Після завершення аналізу вбийте процес:

```bash
kill -9 <PID>
```
